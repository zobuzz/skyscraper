# Skyscraper

A Unity 2D reimplementation of the Douyin mini-game **关关难不住** — a
tower-defense/Tetris hybrid. You drop polyomino bricks onto a pedestal; each
brick carries a hero that attacks the monsters walking in; kills pay gold; gold
buys the next brick. Bricks that miss the stack fall away and are lost.

Built by driving the Unity editor over MCP. Every geometric constant in the
codebase is a measurement off the original, not a guess — see
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for how that is kept honest.

> **Status: playable prototype.** The battle loop, brick physics, merging,
> waves, height bonus and HUD all work. Input is still keyboard/mouse rather
> than touch, and figure animation is a single baked pose driven procedurally
> rather than real frame sequences. See [Known gaps](#known-gaps).

---

## Requirements

| | |
|---|---|
| Unity | **2022.3.62f1** (`ProjectSettings/ProjectVersion.txt`) |
| Render pipeline | URP 14.0.12 |
| Template | 2D |

Other 2022.3.x patch releases will very likely open it fine. The original
game was built with 2022.3.62f3c1 (the China WebGL fork), which is why this
version was chosen.

## Getting started

```bash
git clone <this repo> skyscraper
```

Open the folder in Unity Hub. First import takes a few minutes while the
`Library/` cache is built from scratch — that directory is intentionally not
committed (it is 2.3 GB).

Then:

1. Open `Assets/Scenes/Battle.unity`.
2. If the scene looks empty, run **Skyscraper → Build Battle Scene** from the
   menu bar. The scene is generated by `Assets/Editor/BattleSceneBuilder.cs`
   rather than hand-authored, so this is the normal way to get it into a known
   state — and it is idempotent.
3. Press Play.

`Skyscraper → Validate Config Tables` sanity-checks the JSON in
`StreamingAssets/GameConfig` against the types in `Scripts/Config`, and is
worth running after touching either.

### Controls

Keyboard and mouse only right now (`Brick/BrickDropper.cs:256-273`):

| Input | Action |
|---|---|
| `1` `2` `3` | pick one of the three offered cards |
| Left-drag / release | position and drop the brick |
| `Q` or right-click | rotate the held brick |
| `R` | reroll the hand |

These are unreachable on a phone, which is the first item under
[Known gaps](#known-gaps).

## What is in the box

```
Assets/
  Scenes/Battle.unity          the battle scene (generated, see above)
  Editor/
    BattleSceneBuilder.cs      builds the scene; owns the menu items
    BattleSceneAutoBuild.cs    [InitializeOnLoad] rebuild after a fresh import
  Scripts/
    Config/                    JSON table loading + row types
    Battle/                    the game
      Brick/                   footprints, dropping, merging
      Enemy/                   monster units
      Combat/                  projectiles, damage interface
      Art/                     figure sprites + the animation state machine
      Challenge/               per-map modifiers
    Util/                      procedural sprite helpers
  Resources/
    Bricks/                    brick base art        <- NOT COMMITTED
    Figures/{Hero,Enemy}/      hero + monster art    <- NOT COMMITTED
  StreamingAssets/GameConfig/  28 data tables as JSON
```

30 C# files. The two `Resources` folders are gitignored because they hold art
extracted from the original game — **the project compiles and plays without
them**, falling back to flat coloured polygons. See
[docs/ART.md](docs/ART.md) to populate them from your own copy of the game.

## Known gaps

Honest list, roughly in priority order:

- **Touch input.** `Q`/right-click rotate, `1`/`2`/`3` select and `R` reroll
  have no touch equivalent. Card selection should be tap-a-card and reroll
  should be tap-the-`⇄`-button.
- **Figure animation is one pose.** Each hero and monster has a single baked
  setup-pose PNG; the six clips (`Appear`/`Idle`/`Move`/`Attack`/`Hit`/`Death`)
  are driven by procedural transform motion. Baking the real Spine timelines is
  a data-only change — see [docs/ART.md](docs/ART.md#stage-2).
- **Drop-zone band shows during drag** and should be hidden while dragging.
- **Hand refills immediately** after a card is played; the original leaves the
  slot empty and does not shift the others left.
- Unwired art: `break_frame_1..7` (card frames), `UI_yd_5`, and the `building`
  and `join` sprite layers the original brick carries alongside `_` and `merge`.
- Not implemented: `x1` speed toggle, `获取特殊方块(3)` and hammer ad buttons,
  hero icons on cards, `Desk`/`MapColor` art sources, the challenge modifiers
  谨慎决策/沼泽/凝视, the meta progression layer, and camera zoom as the tower
  grows.
- `BrickShape.Oriented`'s doc comment says "clockwise" but the transform is
  counter-clockwise in centred coordinates. The code is correct; the comment
  is not, and it has already caused one wrong derivation. See
  [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#the-orientation-trap).
